# Plan 26-02: Role-Based Tab Filtering + Empty States

**Phase:** 26 — Conversations System Overhaul
**Goal:** DFY users only see Project + Partner tabs (not Workspace). All users get context-aware empty states.
**Depends on:** 26-01 (inquiry comments removal simplifies the Inquiries tab)

---

## Why

Currently all 3 tabs (Inbox, Projects, Inquiries) show for every role. DFY users see Workspace conversations they can't interact with (RLS blocks at DB level but UI still shows them). Empty conversations show generic "No messages yet" instead of explaining the conversation's purpose and visibility scope.

---

## Tasks

### Task 1: Wire role-based tab filtering into ConversationsView

**File:** `app/(dashboard)/conversations/ConversationsView.tsx`

The `getAccessibleTypes()` function already exists in `features/conversations/components/ConversationTabs.tsx` (lines 30-44). Import and use it.

**Changes:**
1. Import `getAccessibleTypes` from `ConversationTabs.tsx` (or inline the logic)
2. Use `userRole` prop (line 22-27, currently accepted but unused) to determine which tabs to render
3. Replace the hardcoded 3-tab structure (lines 240-269) with dynamic tab generation:

```tsx
// Tab config — only render tabs the user's role can access
const accessibleTypes = getAccessibleTypes(userRole)
const tabs = [
  { id: 'inbox', label: 'Inbox', icon: Inbox, data: directConversations, show: true }, // DMs always visible
  { id: 'projects', label: 'Projects', icon: FolderKanban, data: projectConversations, show: accessibleTypes.some(t => ['project', 'workspace', 'partner'].includes(t)) },
  { id: 'inquiries', label: 'Inquiries', icon: FileText, data: inquiryConversations, show: accessibleTypes.includes('inquiry') || userRole === 'admin' || userRole === 'internal' || userRole === 'dfy' },
].filter(tab => tab.show)
```

**Rules:**
- `admin`/`internal`: All 3 tabs
- `dev`: Inbox + Projects (no Inquiries since devs don't submit inquiries)
- `dfy`: Inbox + Projects + Inquiries
- `client`: Inbox + Projects

4. Default `activeTab` to the first available tab instead of hardcoded 'inbox'

### Task 3: Context-aware empty states for conversation list

**File:** `features/conversations/components/ConversationList.tsx`

Replace the generic empty state (lines 111-114) with tab-aware messages:

```tsx
// Replace simple string with context-aware empty state
const getEmptyState = () => {
  if (searchQuery) return { title: 'No results', description: 'Try a different search term' }
  switch (tabId) {
    case 'inbox':
      return { title: 'No direct messages', description: 'Start a conversation with a teammate' }
    case 'projects':
      return { title: 'No project conversations', description: 'Conversations are created automatically when projects start' }
    case 'inquiries':
      return { title: 'No inquiry discussions', description: 'Discussions appear when inquiries are submitted' }
    default:
      return { title: 'No conversations yet', description: '' }
  }
}
```

**Changes:**
1. Add `tabId` prop to `ConversationList` (passed from ConversationsView)
2. Replace the empty state div with a more structured layout:
   - Icon (matching the tab icon)
   - Title (bold, slightly larger)
   - Description (muted, smaller)

### Task 4: Context-aware empty states for chat panel

**File:** `app/(dashboard)/conversations/ConversationsView.tsx`

When a conversation is selected but has zero messages, the ChatPanel should show a welcome message that reinforces visibility scope:

**File:** `features/conversations/components/ChatPanel.tsx`

Add a welcome message when `messages.length === 0`:

```tsx
const getWelcomeMessage = (type: ConversationType) => {
  switch (type) {
    case 'project':
      return 'Messages here are visible to everyone on this project.'
    case 'workspace':
      return 'Only the internal team and assigned developer can see messages here.'
    case 'partner':
      return 'Only the internal team and DFY partner can see messages here.'
    case 'direct':
      return 'This is a private conversation.'
    case 'inquiry':
      return 'Discuss this inquiry with relevant team members.'
    default:
      return 'Start the conversation.'
  }
}
```

Render as a centered, muted text block above the compose area when no messages exist.
