  <name>Task 1: Create Supabase migration for retainer system</name>
  <files>supabase/migrations/20260210000001_retainer_system.sql</files>
  <action>
Create a single migration file that does the following IN ORDER:

1. **Extend project_status enum** — Add 'retainer' value to the project_status enum type. Use `ALTER TYPE project_status ADD VALUE IF NOT EXISTS 'retainer' BEFORE 'completed';`

2. **Add retainer config columns to projects table:**
   - `check_in_cadence` — TEXT, nullable, one of 'weekly', 'biweekly', 'monthly'. Use CHECK constraint, not a new enum.
   - `check_in_assignees` — TEXT[], nullable. Array of role strings ('admin', 'dfy', 'dev') that get pinged.
   - `retainer_dev_ids` — UUID[], nullable. Array of dev user IDs assigned to retainer.
   - `completion_summary` — JSONB, nullable. Stores the completion ceremony snapshot.
   - `completed_at` — TIMESTAMPTZ, nullable. When the project was completed.
   - `retainer_started_at` — TIMESTAMPTZ, nullable. When retainer mode was activated.

3. **Create retainer_check_ins table:**
   ```sql
   CREATE TABLE retainer_check_ins (
     id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
     project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
     health TEXT NOT NULL CHECK (health IN ('green', 'yellow', 'red')),
     notes TEXT,
     submitted_by UUID NOT NULL REFERENCES auth.users(id),
     due_date DATE,
     created_at TIMESTAMPTZ NOT NULL DEFAULT now()
   );
   ```

4. **Create retainer_tasks table:**
   ```sql
   CREATE TABLE retainer_tasks (
     id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
     project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
     title TEXT NOT NULL,
     description TEXT,
     status TEXT NOT NULL DEFAULT 'todo' CHECK (status IN ('todo', 'in_progress', 'done')),
     priority TEXT NOT NULL DEFAULT 'medium' CHECK (priority IN ('low', 'medium', 'high')),
     assignee_id UUID REFERENCES auth.users(id),
     created_by UUID NOT NULL REFERENCES auth.users(id),
     completed_at TIMESTAMPTZ,
     created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
     updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
   );
   ```

5. **Create project_improvements table:**
   ```sql
   CREATE TABLE project_improvements (
     id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
     project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
     title TEXT NOT NULL,
     description TEXT,
     priority TEXT NOT NULL DEFAULT 'nice_to_have' CHECK (priority IN ('nice_to_have', 'important', 'critical')),
     status TEXT NOT NULL DEFAULT 'open' CHECK (status IN ('open', 'converted')),
     converted_project_id UUID REFERENCES projects(id),
     added_by UUID NOT NULL REFERENCES auth.users(id),
     created_at TIMESTAMPTZ NOT NULL DEFAULT now()
   );
   ```

6. **RLS policies for retainer_check_ins:**
   - Enable RLS
   - SELECT: Admin sees all. DFY sees own projects (via projects.dfy_partner_id = auth.uid()). Dev sees if auth.uid() = ANY(projects.retainer_dev_ids).
   - INSERT: Same as SELECT but also require project status = 'retainer'.
   - Use `get_user_role()` function that already exists.

7. **RLS policies for retainer_tasks:**
   - Enable RLS
   - SELECT: Same role-based pattern as check-ins (admin all, DFY own, dev assigned).
   - INSERT: Same as check-ins SELECT + project must be in retainer or completed status.
   - UPDATE: Same as INSERT (team members can update tasks).
   - DELETE: Admin only.

8. **RLS policies for project_improvements:**
   - Enable RLS
   - SELECT: Admin sees all. DFY sees own projects. Dev sees assigned projects (either assigned_dev_id or retainer_dev_ids).
   - INSERT: Same as SELECT (anyone on team can add).
   - UPDATE: Admin only (for status changes to 'converted').
   - DELETE: Admin only.

9. **Create indexes:**
   - `retainer_check_ins(project_id, created_at DESC)`
   - `retainer_tasks(project_id, status)`
   - `project_improvements(project_id, status)`

10. **Add updated_at trigger for retainer_tasks** using the existing `update_updated_at_column` trigger function (check it exists in prior migrations first, create if not).

IMPORTANT: Follow the manual type definition pattern. No generated types. All RLS policies must use the existing `get_user_role()` function. Reference the pattern from `20241221000001_initial_schema.sql` for RLS.
