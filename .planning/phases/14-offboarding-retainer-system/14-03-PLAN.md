**1. Create lib/api/retainer-check-ins.ts:**

Follow the manual type definition pattern (no generated Supabase types).

```typescript
import { createClient } from '@/lib/supabase/server'

export type CheckInHealth = 'green' | 'yellow' | 'red'

export interface RetainerCheckIn {
  id: string
  project_id: string
  health: CheckInHealth
  notes: string | null
  submitted_by: string
  due_date: string | null
  created_at: string
  submitter?: {
    id: string
    name: string
  }
}

export interface LogCheckInInput {
  projectId: string
  health: CheckInHealth
  notes?: string
}
```

Functions to implement:

- `getRetainerCheckIns(projectId: string)`: Fetch all check-ins for a project, ordered by created_at DESC. Join with profiles for submitter name. Return as `RetainerCheckIn[]`.

- `logCheckIn(input: LogCheckInInput)`: Insert a new check-in record. Use `(await createClient())` to get current user ID for `submitted_by`. Return the created check-in.

- `getNextCheckInDueDate(projectId: string)`: Calculate the next due date based on project's check_in_cadence and the most recent check-in. Logic:
  - Fetch most recent check-in `created_at`
  - Fetch project's `check_in_cadence`
  - Calculate next due: `lastCheckIn.created_at + cadenceDays` where weekly=7, biweekly=14, monthly=30
  - If no check-ins exist, use `retainer_started_at + cadenceDays`
  - Return `{ dueDate: string, isOverdue: boolean }` where isOverdue = dueDate < today

- `getLatestCheckIn(projectId: string)`: Fetch only the most recent check-in for dashboard display. Return `RetainerCheckIn | null`.

**2. Create lib/api/retainer-tasks.ts:**

```typescript
import { createClient } from '@/lib/supabase/server'

export type TaskStatus = 'todo' | 'in_progress' | 'done'
export type TaskPriority = 'low' | 'medium' | 'high'

export interface RetainerTask {
  id: string
  project_id: string
  title: string
  description: string | null
  status: TaskStatus
  priority: TaskPriority
  assignee_id: string | null
  created_by: string
  completed_at: string | null
  created_at: string
  updated_at: string
  assignee?: {
    id: string
    name: string
  }
  creator?: {
    id: string
    name: string
  }
}

export interface CreateRetainerTaskInput {
  projectId: string
  title: string
  description?: string
  priority?: TaskPriority
  assigneeId?: string
}

export interface UpdateRetainerTaskInput {
  title?: string
  description?: string
  status?: TaskStatus
  priority?: TaskPriority
  assigneeId?: string | null
}
```

Functions to implement:

- `getRetainerTasks(projectId: string)`: Fetch all tasks for a project. Join with profiles for assignee and creator names. Order by: status ASC (todo first, done last), then priority DESC (high first), then created_at DESC. Return as `RetainerTask[]`.

- `getRetainerTaskCounts(projectId: string)`: Return `{ todo: number, in_progress: number, done: number, total: number }` for dashboard display.

- `createRetainerTask(input: CreateRetainerTaskInput)`: Insert new task. Use current user for `created_by`. Return created task.

- `updateRetainerTask(taskId: string, input: UpdateRetainerTaskInput)`: Update task fields. If status changes to 'done', set `completed_at = now()`. If status changes from 'done' to something else, set `completed_at = null`. Return updated task.

- `deleteRetainerTask(taskId: string)`: Delete a task. Admin-only (enforced by RLS).

All functions follow the Supabase client pattern: `const supabase = await createClient()`. Use `select()` with join syntax for relations. Throw on error (server actions will catch).

**Server actions to implement:**

1. `logCheckInAction(params: { projectId: string, health: CheckInHealth, notes?: string })`:
   - Call `logCheckIn(params)`
   - If health is 'yellow' or 'red', check previous check-in health. If this is a downgrade (green→yellow, green→red, yellow→red), send `retainer_health_warning` notification to admin.
   - Fetch project to get admin info for notification. Use a known admin lookup pattern (check if `createNotification` supports it or find admin users).
   - Actually, for simplicity: if health != 'green', always send `retainer_health_warning` to all admins. Look up admins via profiles table where role = 'admin'.
   - `revalidatePath(/projects/${params.projectId})`
   - Return `{ data: checkIn }` or `{ error: string }`

2. `createRetainerTaskAction(params: { projectId: string, title: string, description?: string, priority?: TaskPriority, assigneeId?: string })`:
   - Call `createRetainerTask(params)`
   - If assigneeId is provided, send `retainer_task_assigned` notification to assignee
   - `revalidatePath(/projects/${params.projectId})`
   - Return `{ data: task }` or `{ error: string }`

3. `updateRetainerTaskAction(params: { taskId: string, projectId: string } & UpdateRetainerTaskInput)`:
   - Call `updateRetainerTask(taskId, input)`
   - If assigneeId changed (was null or different), send `retainer_task_assigned` notification to new assignee
   - `revalidatePath(/projects/${params.projectId})`
   - Return `{ data: task }` or `{ error: string }`

4. `deleteRetainerTaskAction(params: { taskId: string, projectId: string })`:
   - Call `deleteRetainerTask(params.taskId)`
   - `revalidatePath(/projects/${params.projectId})`
   - Return `{ data: { success: true } }` or `{ error: string }`

5. `updateRetainerConfigAction(params: { projectId: string, checkInCadence?: string, checkInAssignees?: string[], retainerDevIds?: string[] })`:
   - Call `updateProject(params.projectId, { ... })` to update retainer config fields
   - If retainerDevIds changed and devs were removed: fetch current tasks assigned to removed devs and unassign them (set assignee_id = null)
   - `revalidatePath(/projects/${params.projectId})`
   - Return `{ data: { success: true } }` or `{ error: string }`

All actions follow the structured result pattern: try/catch with console.error, return `{ data }` on success, `{ error: string }` on failure.

For admin lookup in notifications, use a helper:
```typescript
async function getAdminUserIds(): Promise<string[]> {
  const supabase = await createClient()
  const { data } = await supabase
    .from('profiles')
    .select('id')
    .eq('role', 'admin')
  return (data || []).map(p => p.id)
}
```
