**Check-in overdue cron (`app/api/cron/check-in-overdue/route.ts`):**

Create a GET handler that:
1. Validates authorization header against `CRON_SECRET` env var. Return 401 if invalid.
2. Uses admin supabase client (from `@/lib/supabase/admin`) to query retainer projects with overdue check-ins.
3. Query logic:
   - Get projects with `project_status = 'retainer'` that have `retainer_started_at` set
   - For each, calculate next check-in due date using: last check-in date + cadence days (weekly=7, biweekly=14, monthly=30). If no check-ins exist, use retainer_started_at + cadence.
   - If due date is in the past, the check-in is overdue
4. For overdue check-ins, send notifications:
   - `retainer_check_in_overdue` to assigned devs (from `retainer_dev_ids` or project assignments)
   - `retainer_check_in_overdue` to admins via notifyAdmins
5. Use a deduplication strategy: only notify if no `retainer_check_in_overdue` notification exists for this project in the last 24 hours (prevents daily spam). Query `notifications` table before creating.
6. Return JSON with count of overdue projects found and notifications sent.

Use `createAdminClient()` from `@/lib/supabase/admin` for direct DB access (cron has no user session). Import `createNotification` and use the admin client for notification inserts directly (since createNotification uses server client with cookies). Alternative: create notifications using admin client's `.from('notifications').insert()` since cron routes can't use cookie-based auth. BUT also call sendPushNotification directly for push support.

Actually — check how the existing testing check-escalations route handles this. If it uses admin client with raw inserts, follow that pattern. If the admin createClient pattern works differently, adapt.

**Deadline reminder cron (`app/api/cron/deadline-reminders/route.ts`):**

Create a GET handler that:
1. Validates CRON_SECRET authorization.
2. Queries deliverables with upcoming due dates (within 3 days, or within 1 day).
3. For each deliverable approaching deadline:
   - Get the assigned dev (if any) from project assignments
   - Create `deadline_reminder` notification for the assigned dev
   - Create `deadline_reminder` notification for admins
4. Deduplication: only notify if no `deadline_reminder` for this deliverable exists in last 24 hours.
5. Return JSON summary.

Query deliverables where `due_date` is between now and now+3days AND status is not 'completed'/'approved'. Join with projects for project name context.

Both endpoints follow the pattern:
```typescript
import { NextResponse } from 'next/server'
import { createAdminClient } from '@/lib/supabase/admin'

export async function GET(request: Request) {
  // Auth check
  const authHeader = request.headers.get('authorization')
  if (authHeader !== `Bearer ${process.env.CRON_SECRET}`) {
    return NextResponse.json({ error: 'Unauthorized' }, { status: 401 })
  }

  const supabase = createAdminClient()
  // ... query and notify logic
  return NextResponse.json({ processed: count, notified: notifiedCount })
}
```
