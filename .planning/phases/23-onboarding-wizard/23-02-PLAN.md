**Step 2: Create the onboarding server page**

Create `app/(onboarding)/onboarding/page.tsx`:

```tsx
import { redirect } from 'next/navigation'
import { getAuthUser, getAuthProfile } from '@/lib/auth/cached'
import { DASHBOARD_ROUTES, type Profile } from '@/lib/auth/types'
import { OnboardingWizard } from '@/features/onboarding/components/OnboardingWizard'
import { getUserMembership } from '@/lib/api/organizations'

export default async function OnboardingPage() {
  const { user, error: authError } = await getAuthUser()

  if (authError || !user) {
    redirect('/login')
  }

  const profile = await getAuthProfile()

  if (!profile) {
    redirect('/login')
  }

  // Already completed onboarding — go to dashboard
  if ((profile as Profile).has_completed_onboarding) {
    redirect(DASHBOARD_ROUTES[(profile as Profile).role] || '/dashboard')
  }

  // Get org info for DFY role step 2 content
  const membership = await getUserMembership(user.id).catch(() => null)

  return (
    <OnboardingWizard
      userId={user.id}
      profile={profile as Profile}
      organizationName={membership?.organization?.name || null}
      isOrgOwner={membership?.role === 'owner'}
    />
  )
}
```

**Key points:**
- Server component — auth check happens server-side
- Three guards: (1) no auth → /login, (2) no profile → /login, (3) already onboarded → dashboard
- `getUserMembership()` provides org name + owner/member distinction for DFY step 2
- `.catch(() => null)` handles non-DFY users who have no org membership
- Passes `isOrgOwner` boolean so wizard can show different DFY copy
- Uses `(profile as Profile)` for the type assertion since `getAuthProfile()` returns `Profile | null` and we've guarded against null above

**Step 1 — Profile Completion:**
- Card with title "Complete your profile"
- Display name input (pre-filled from profile or empty)
- Timezone select or input (pre-filled from browser `Intl.DateTimeFormat().resolvedOptions().timeZone`)
- Show the user's email as read-only info (not editable — comes from auth)
- If `profile.avatar_url` exists (from Google OAuth), show it as a small avatar preview
- "Continue" button advances to step 2
- Name is required — disable Continue if name is empty

**Step 2 — Role-Specific Intro:**
Use a `switch (profile.role)` to render role-specific content:

| Role | Content |
|------|---------|
| `admin` / `internal` | "Welcome to the team" heading. Brief bullet list: manage inquiries, track projects, monitor team activity. Icon: Shield or Settings from lucide-react. |
| `dfy` (isOrgOwner=true) | "Your agency is set up" heading. Show org name. Bullets: invite teammates, manage projects, track deliverables. Icon: Building2. |
| `dfy` (isOrgOwner=false) | "You've joined {orgName}" heading. Bullets: collaborate with team, track assigned work, communicate with clients. Icon: Users. |
| `dev` | "Welcome to the dev network" heading. Bullets: find projects, track your work, build your profile. Note: "You can set up skills and availability in Settings." Icon: Code. |
| `client` | "Your project dashboard" heading. Bullets: track project progress, communicate with team, review deliverables. Icon: LayoutDashboard. |

Each role section is a Card with an icon, heading, description text, and 2-4 bullet points using `lucide-react` icons.

"Continue" button advances to step 3.

**Step 3 — Done / Complete:**
- "You're all set!" heading with a CheckCircle2 icon
- Brief message: "Let's get started."
- "Go to Dashboard" button that:
  1. Calls `completeOnboarding({ name, timezone })` via `startTransition`
  2. On success: `router.push(DASHBOARD_ROUTES[profile.role] || '/dashboard')`
  3. On error: `toast.error(result.error || 'Failed to complete onboarding')`
- Show loading state on button while `isPending`

**Step indicator:**
