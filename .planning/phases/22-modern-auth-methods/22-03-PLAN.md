```tsx
// Server action for Google OAuth on invite page
async function handleGoogleSignIn() {
  'use server'

// Server action for magic link on invite page
async function handleMagicLink() {
  'use server'
  const result = await signInWithMagicLink(invitation.email, token)
  if (!result.success) {
    redirect(`/invite/${token}?error=${encodeURIComponent(result.error || 'Failed to send magic link')}`)
  }
  redirect(`/invite/${token}?success=magic-link&mode=${mode}`)
}
```

**NOTE — Override of research Pattern 6:** The research document (22-RESEARCH.md Pattern 6) shows `?error=` for the magic link success redirect. This plan intentionally uses `?success=magic-link` instead, which is the correct approach — using `?error=` for a success message is misleading and renders with error (red) styling. The `?success=` param renders with success (cyan) styling. This plan's approach takes precedence over the research pattern.
