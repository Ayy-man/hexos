<task type="auto">
  <name>Task 1: Create meeting API helpers at lib/api/meetings.ts</name>
  <files>lib/api/meetings.ts</files>
  <action>
Create the meetings API helper module following the exact pattern from `lib/api/invoices.ts`: use `createClient` from `@/lib/supabase/admin` for server-side operations, return `{success, data?, error?}` for mutations, return data or empty arrays for queries.

Implement these functions:

1. **detectPlatform(url: string): MeetingPlatform | null** — Parse meeting URL to detect platform:
   - Contains 'zoom.us' -> 'zoom'
   - Contains 'meet.google.com' -> 'google_meet'
   - Contains 'teams.microsoft.com' or 'teams.live.com' -> 'teams'
   - Otherwise -> 'other' (don't return null, accept any URL as 'other')

2. **getMeetings(filters?)** — List meetings with optional filters: status, projectId (via meeting_links join), inquiryId (via meeting_links join), from/to date range, limit. Order by created_at desc. Select meetings with a left join on meeting_links to get linked entity names. Return `Meeting[]`.

3. **getMeeting(id)** — Get single meeting with all related data: meeting_links, meeting_participants, meeting_tasks. Use separate queries for each relation (not a massive join). Return `MeetingWithLinks | null`.

4. **createMeeting(input, userId)** — Create meeting record + dispatch Recall.ai bot + create meeting_links:
   - Detect platform from URL
   - Insert meeting with status 'pending', created_by = userId
   - Call `recall.createBot({ meeting_url })` from `@/lib/recall/client`
   - Update meeting with recall_bot_id and status 'joining'
   - If input.links provided, insert meeting_links rows
   - Return `{success: true, data: meeting}` or `{success: false, error}`
   - If Recall.ai fails, still return the meeting (with status 'pending') and log the error — don't fail the whole creation

5. **updateMeeting(id, updates)** — Update meeting title. Return `{success, error?}`.

6. **deleteMeeting(id)** — Delete meeting (cascade handles related rows). Return `{success, error?}`.

7. **addMeetingLink(meetingId, linkableType, linkableId)** — Insert a meeting_link row. Return `{success, error?}`.

8. **removeMeetingLink(linkId)** — Delete a meeting_link row. Return `{success, error?}`.

9. **getMeetingsForEntity(linkableType, linkableId)** — Get all meetings linked to a specific project/inquiry. Query meeting_links where linkable_type and linkable_id match, then fetch the meetings. Return `Meeting[]`. This is used for the project detail "Meetings" tab.

Import types from `@/lib/types/meetings`. Import `recall` from `@/lib/recall/client`. Import `createClient` from `@/lib/supabase/admin`.

Do NOT use createClient from `@/lib/supabase/server` — use admin client since this runs in API routes/server actions, not in user-authenticated context. Follow the invoices.ts pattern exactly.

  <files>app/api/meetings/route.ts, app/api/meetings/[id]/route.ts, app/api/meetings/[id]/links/route.ts</files>
  <action>
Create three route files:

**app/api/meetings/route.ts** (GET + POST):
- GET: Parse query params (status, project_id, inquiry_id, from, to, limit). Call getMeetings(filters). Return JSON response.
- POST: Parse JSON body (title, meeting_url, links?). Get authenticated user from supabase auth. Call createMeeting(input, userId). Return 201 on success, 400 on error.
- Both handlers: Check auth with `createClient()` from `@/lib/supabase/server`, verify user exists, return 401 if not.

**app/api/meetings/[id]/route.ts** (GET + PATCH + DELETE):
- GET: Call getMeeting(id). Return 404 if null.
- PATCH: Parse JSON body, call updateMeeting(id, updates). Return result.
- DELETE: Call deleteMeeting(id). Return result.
- All handlers require auth check.

**app/api/meetings/[id]/links/route.ts** (POST + DELETE):
- POST: Parse body {linkable_type, linkable_id}. Call addMeetingLink(meetingId, type, id). Return 201.
- DELETE: Parse body {link_id} or use searchParams. Call removeMeetingLink(linkId). Return result.
- Both require auth check.

Follow the pattern from existing API routes: use NextRequest/NextResponse, parse params from context, handle errors with try/catch returning 500.

For auth in API routes, use this pattern:
```typescript
const supabase = await createClient()
const { data: { user } } = await supabase.auth.getUser()
if (!user) return NextResponse.json({ error: 'Unauthorized' }, { status: 401 })
```

Import createClient from `@/lib/supabase/server` for auth checks in routes. The lib/api/meetings.ts functions use the admin client internally.
