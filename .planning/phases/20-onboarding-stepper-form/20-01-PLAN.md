Create a Supabase migration file with the following:

**1. onboarding_categories table:**
```sql
CREATE TABLE public.onboarding_categories (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id uuid NOT NULL REFERENCES public.projects(id) ON DELETE CASCADE,
  title text NOT NULL,
  description text,
  position int NOT NULL DEFAULT 0,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now()
);
```

**2. onboarding_questions table:**
```sql
CREATE TABLE public.onboarding_questions (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id uuid NOT NULL REFERENCES public.projects(id) ON DELETE CASCADE,
  category_id uuid NOT NULL REFERENCES public.onboarding_categories(id) ON DELETE CASCADE,
  title text NOT NULL,
  description text,
  question_type text NOT NULL CHECK (question_type IN ('text','textarea','select','multi_select','boolean')),
  options jsonb,
  is_required boolean NOT NULL DEFAULT false,
  position int NOT NULL DEFAULT 0,
  created_at timestamptz NOT NULL DEFAULT now()
);
```

**3. onboarding_answers table:**
```sql
CREATE TABLE public.onboarding_answers (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  question_id uuid NOT NULL REFERENCES public.onboarding_questions(id) ON DELETE CASCADE,
  project_id uuid NOT NULL REFERENCES public.projects(id) ON DELETE CASCADE,
  answered_by uuid REFERENCES public.profiles(id),
  value jsonb,
  answered_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT onboarding_answers_question_project_unique UNIQUE (question_id, project_id)
);
```

**4. Extend onboarding_requirements:**
```sql
ALTER TABLE public.onboarding_requirements
  ADD COLUMN IF NOT EXISTS category_id uuid REFERENCES public.onboarding_categories(id) ON DELETE SET NULL;
```

**5. Indexes:**
- `idx_onboarding_categories_project` on `onboarding_categories(project_id)`
- `idx_onboarding_questions_project` on `onboarding_questions(project_id)`
- `idx_onboarding_questions_category` on `onboarding_questions(category_id)`
- `idx_onboarding_answers_project` on `onboarding_answers(project_id)`
- `idx_onboarding_answers_question` on `onboarding_answers(question_id)`
- `idx_onboarding_requirements_category` on `onboarding_requirements(category_id)`

**6. Triggers:**
- Auto-update `updated_at` on `onboarding_categories` using existing `handle_updated_at()` function
- Auto-update `updated_at` on `onboarding_answers` using existing `handle_updated_at()` function

**7. RLS policies:**
Enable RLS on all three new tables. Use the existing `can_access_project()` function and `get_user_role()` function (see migration 20260103000008):

For `onboarding_categories`:
- Admin/internal: full access (`FOR ALL`)
- Project members: SELECT via `can_access_project(project_id)`

For `onboarding_questions`:
- Admin/internal: full access (`FOR ALL`)
- Project members: SELECT via `can_access_project(project_id)`

For `onboarding_answers`:
- Admin/internal: full access (`FOR ALL`)
- Project members: SELECT via `can_access_project(project_id)`
- DFY: INSERT and UPDATE where `can_access_project(project_id)` — DFY must be able to write answers for their own projects
- Important: Use separate INSERT (WITH CHECK) and UPDATE (USING + WITH CHECK) policies for DFY, not a single FOR ALL

Follow the exact RLS pattern from `20260101000001_onboarding_requirements.sql`.

Create `features/projects/actions/onboardingFormActions.ts` with `'use server'` directive.

All actions follow the pattern: authenticate user, call API function, return `{ success: boolean; error?: string }`. Use `revalidatePath` only on explicit user actions (add/delete category, add/delete question, mark complete) — NOT on auto-save answer saves (to avoid full page re-renders on every keystroke, per RESEARCH.md anti-pattern guidance).

**Answer actions:**
- `saveAnswerAction(projectId: string, questionId: string, value: string | boolean | string[] | null)` — authenticate, call `upsertOnboardingAnswer`. Catch FK/not-found errors and return `{ success: false, error: 'section_deleted' }` specifically when the question or category was deleted (per Pitfall 6 in RESEARCH.md). Do NOT call `revalidatePath` here.

**Category actions (admin only):**
- `addCategoryAction(projectId: string, title: string, description?: string)` — create category with position = next available. `revalidatePath('/projects/' + projectId)`.
- `updateCategoryAction(categoryId: string, input: { title?: string; description?: string | null })` — update. `revalidatePath`.
- `deleteCategoryAction(categoryId: string, projectId: string)` — delete. `revalidatePath`.
- `reorderCategoriesAction(projectId: string, updates: Array<{ id: string; position: number }>)` — reorder. `revalidatePath`.

**Question actions (admin only):**
- `addQuestionAction(projectId: string, categoryId: string, data: { title: string; question_type: QuestionType; description?: string; options?: string[]; is_required?: boolean })` — create with position = next available. `revalidatePath`.
- `updateQuestionAction(questionId: string, input: UpdateOnboardingQuestionInput)` — update. No revalidate (inline optimistic UI handles it).
- `deleteQuestionAction(questionId: string, projectId: string)` — delete. `revalidatePath`.
- `reorderQuestionsAction(projectId: string, updates: Array<{ id: string; position: number }>)` — reorder. `revalidatePath`.

**Completion action:**
- `markOnboardingCompleteAction(projectId: string)` — This is the server-side re-validation action. Query all required questions (`is_required = true`) for the project, check if each has an answer in `onboarding_answers`. If any required question lacks an answer, return `{ success: false, error: 'incomplete', incompleteCategories: string[] }` with the category IDs that have missing required answers. If all required questions answered, update the project status (use existing status transition pattern). `revalidatePath`.

Import types from the new API files. Use `createClient` from `@/lib/supabase/server` for auth checks. Log errors with `console.error('[actionName] FAILED:', error)` per conventions.
