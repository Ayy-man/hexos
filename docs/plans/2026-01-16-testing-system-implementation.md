# Testing System Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build a multi-stage testing workflow for deliverables with Dev → Admin/INT → Client sequential gates, AI-suggested checklists, automated blocker creation, and a dedicated Testing tab.

**Architecture:**
- Three sequential testing stages (dev, admin_int, client) - each must pass before next unlocks
- Separate checklist tables per stage with visibility into previous stage results
- Testing tab conditionally renders when any deliverable hits 90%
- Failed checklist items auto-create individual blockers linked to test items
- Hill chart position updates based on which stage passed (90% → 95% → 100%)

**Tech Stack:**
- Supabase (PostgreSQL) for data model with RLS
- Next.js App Router for UI
- TypeScript for type safety
- Lucide React for icons
- Existing notification system extended with new types

  'edge_cases',    -- Edge cases and error handling

  'security',      -- RLS, permissions, auth
  'ui_responsive', -- Mobile/responsive testing
  'custom'         -- Custom acceptance criteria

-- 2. Test sessions table - one per deliverable per stage
-- ============================================

CREATE TABLE IF NOT EXISTS deliverable_tests (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  deliverable_id UUID NOT NULL REFERENCES deliverables(id) ON DELETE CASCADE,

  -- Which testing stage this session is for
  stage testing_stage NOT NULL,

  -- Status of this testing stage
  status test_status DEFAULT 'pending',

  -- Who is/was testing and when
  tested_by UUID REFERENCES profiles(id),
  started_at TIMESTAMPTZ,
  completed_at TIMESTAMPTZ,

  -- Summary counts

  passed_items INTEGER DEFAULT 0,
  failed_items INTEGER DEFAULT 0,

  -- Notes from the tester
  notes TEXT,

  -- Timestamps
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),

  -- Ensure one test session per stage per deliverable
  UNIQUE(deliverable_id, stage)
);

COMMENT ON COLUMN deliverable_tests.stage IS 'Testing stage: dev (self-test), admin_int (internal QA), client (UAT)';

-- Get the current testing stage for a deliverable
CREATE OR REPLACE FUNCTION get_current_testing_stage(p_deliverable_id UUID)
RETURNS testing_stage AS $$
DECLARE
  v_stage testing_stage;
BEGIN
  -- If no tests exist, return 'dev' as the first stage
  -- If dev passed, return 'admin_int'
  -- If admin_int passed, return 'client'
  -- If client passed, return 'client' (done)

  SELECT COALESCE(
    (SELECT stage FROM deliverable_tests
     WHERE deliverable_id = p_deliverable_id
     AND status = 'passed'
     ORDER BY
       CASE stage
         WHEN 'dev' THEN 1
         WHEN 'admin_int' THEN 2
         WHEN 'client' THEN 3
       END DESC
     LIMIT 1),
    'dev'
  ) INTO v_stage;

  -- If the last passed stage was 'client', we're done
  IF v_stage = 'client' THEN
    RETURN 'client';
  END IF;

  -- Return the NEXT stage to test
  RETURN CASE v_stage
    WHEN 'dev' THEN 'admin_int'
    WHEN 'admin_int' THEN 'client'
    ELSE 'dev'
  END;
END;
$$ LANGUAGE plpgsql STABLE;

COMMENT ON FUNCTION get_current_testing_stage IS 'Returns the next testing stage that should run for a deliverable';

-- Check if deliverable is ready for a specific testing stage
CREATE OR REPLACE FUNCTION is_ready_for_testing_stage(p_deliverable_id UUID, p_stage testing_stage)
RETURNS BOOLEAN AS $$
DECLARE
  v_prev_stage testing_stage;
  v_prev_passed BOOLEAN;
BEGIN
  -- Dev stage is ready when deliverable hits 90%
  IF p_stage = 'dev' THEN
    RETURN EXISTS (
      SELECT 1 FROM deliverables
      WHERE id = p_deliverable_id
      AND hill_position >= 90
    );
  END IF;

  -- Other stages require previous stage to be passed
  v_prev_stage := CASE p_stage
    WHEN 'admin_int' THEN 'dev'
    WHEN 'client' THEN 'admin_int'
    ELSE NULL
  END;

  IF v_prev_stage IS NULL THEN
    RETURN FALSE;
  END IF;

  SELECT EXISTS (
    SELECT 1 FROM deliverable_tests
    WHERE deliverable_id = p_deliverable_id
    AND stage = v_prev_stage
    AND status = 'passed'
  ) INTO v_prev_passed;

  RETURN v_prev_passed;
END;
$$ LANGUAGE plpgsql STABLE;

COMMENT ON FUNCTION is_ready_for_testing_stage IS 'Check if a deliverable is ready for a specific testing stage';

-- Auto-update deliverable hill_position based on testing progress
CREATE OR REPLACE FUNCTION update_hill_position_from_testing()
RETURNS TRIGGER AS $$
DECLARE
  v_deliverable_id UUID;
  v_new_position INTEGER;
BEGIN
  IF TG_TABLE_NAME = 'deliverable_tests' THEN
    v_deliverable_id := NEW.deliverable_id;

    -- Update position based on which stage passed
    IF NEW.status = 'passed' THEN
      v_new_position := CASE NEW.stage
        WHEN 'dev' THEN 90
        WHEN 'admin_int' THEN 95
        WHEN 'client' THEN 100
        ELSE 90
      END;

      UPDATE deliverables
      SET hill_position = v_new_position,
          updated_at = NOW()
      WHERE id = v_deliverable_id;
    END IF;
  END IF;

  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- Trigger for auto-updating hill position
DROP TRIGGER IF EXISTS trg_update_hill_from_testing ON deliverable_tests;
CREATE TRIGGER trg_update_hill_from_testing
  AFTER UPDATE ON deliverable_tests
  FOR EACH ROW
  WHEN (OLD.status IS DISTINCT FROM NEW.status AND NEW.status = 'passed')
  EXECUTE FUNCTION update_hill_position_from_testing();

COMMENT ON FUNCTION update_hill_position_from_testing IS 'Auto-update deliverable hill position when testing stage passes';

export interface SubmitTestResultsParams {
  testId: string
  notes?: string
  // Auto-creates blockers for failed items
  createBlockers?: boolean
}

/**
 * Submit test results and complete the testing session
 */
export async function submitTestResults(params: SubmitTestResultsParams): Promise<{
  test: DeliverableTest
  blockersCreated: string[]
}> {
  const supabase = await createClient()
  const { data: { user } } = await supabase.auth.getUser()

  if (!user) throw new Error('Not authenticated')

  // Get the test session with items
  const test = await getTestSession(params.testId)
  if (!test) throw new Error('Test session not found')

  // Calculate results
  const totalItems = test.items.length
  const passedItems = test.items.filter(i => i.passed === true).length
  const failedItems = test.items.filter(i => i.passed === false).length
  const untestedItems = test.items.filter(i => i.passed === null).length

  if (untestedItems > 0) {
    throw new Error(`${untestedItems} items have not been tested yet`)
  }

  const status: TestStatus = failedItems > 0 ? 'failed' : 'passed'

  // Update test session
  const { data: updatedTest, error: updateError } = await supabase
    .from('deliverable_tests')
    .update({
      status,
      total_items: totalItems,
      passed_items: passedItems,
      failed_items: failedItems,
      notes: params.notes || null,
      completed_at: new Date().toISOString(),
    })
    .eq('id', params.testId)
    .select()
    .single()

  if (updateError) throw updateError

  // Create blockers for failed items if requested
  const blockersCreated: string[] = []

  if (params.createBlockers && failedItems > 0) {
    // Get deliverable and project info for blockers
    const { data: deliverable } = await supabase
      .from('deliverables')
      .select('project_id, title')
      .eq('id', test.deliverable_id)
      .single()

    if (deliverable) {
      for (const item of test.items) {
        if (item.passed === false && !item.blocker_id) {
          // Create blocker
          const { data: blocker } = await supabase
            .from('blockers')
            .insert({
              project_id: deliverable.project_id,
              deliverable_id: test.deliverable_id,
              title: `Test failed: ${item.description}`,
              description: item.failure_reason || 'Test item failed during testing',
              priority: 'medium',
              reported_by: user.id,
              test_item_id: item.id,
            })
            .select('id')
            .single()

          if (blocker) {
            // Link the blocker to the test item
            await supabase
              .from('test_checklist_items')
              .update({ blocker_id: blocker.id })
              .eq('id', item.id)

            blockersCreated.push(blocker.id)
          }
        }
      }
    }
  }

  return {
    test: updatedTest,
    blockersCreated,
  }
}

 * Get all deliverables ready for testing across all projects
 */
export async function getTestingQueue(): Promise<{
  readyForDev: DeliverableTestSummary[]
  readyForAdminInt: DeliverableTestSummary[]
  readyForClient: DeliverableTestSummary[]
  inProgress: DeliverableTestSummary[]
}> {
  const supabase = await createClient()

  // Get deliverables at 90% or higher
  const { data: deliverables, error } = await supabase
    .from('deliverables')
    .select(`
      id,
      title,
      hill_position,
      project_id,
      deliverable_tests(id, stage, status)
    `)
    .gte('hill_position', 90)
    .lt('hill_position', 100)

  if (error) throw error

  const summaries: DeliverableTestSummary[] = (deliverables || []).map(d => {
    const tests = d.deliverable_tests || []
    const devTest = tests.find(t => t.stage === 'dev')
    const adminIntTest = tests.find(t => t.stage === 'admin_int')
    const clientTest = tests.find(t => t.stage === 'client')

    // Determine current and next stage
    let currentStage: TestingStage = 'dev'
    let nextStage: TestingStage | null = 'dev'

    if (!devTest || devTest.status === 'pending') {
      currentStage = 'dev'
      nextStage = 'dev'
    } else if (devTest.status === 'passed') {
      if (!adminIntTest || adminIntTest.status === 'pending') {
        currentStage = 'dev'
        nextStage = 'admin_int'
      } else if (adminIntTest.status === 'passed') {
        if (!clientTest || clientTest.status === 'pending') {
          currentStage = 'admin_int'
          nextStage = 'client'
        } else {
          currentStage = 'client'
          nextStage = null
        }
      } else {
        currentStage = 'admin_int'
        nextStage = null
      }
    } else {
      currentStage = 'dev'
      nextStage = null
    }

    return {
      deliverable_id: d.id,
      deliverable_title: d.title,
      current_stage: currentStage,
      dev_status: devTest?.status ?? 'pending',
      admin_int_status: adminIntTest?.status ?? 'pending',
      client_status: clientTest?.status ?? 'pending',
      is_ready_for_next: nextStage !== null,
      next_stage: nextStage,
    }
  })

  // Categorize
  const readyForDev = summaries.filter(
    s => s.dev_status === 'pending' && s.current_stage === 'dev'
  )
  const readyForAdminInt = summaries.filter(
    s => s.dev_status === 'passed' && s.admin_int_status === 'pending'
  )
  const readyForClient = summaries.filter(
    s => s.admin_int_status === 'passed' && s.client_status === 'pending'
  )
  const inProgress = summaries.filter(
    s => s.dev_status === 'in_progress' ||
         s.admin_int_status === 'in_progress' ||
         s.client_status === 'in_progress'
  )

  return {
    readyForDev,
    readyForAdminInt,
    readyForClient,
    inProgress,
  }
}

import { createClient } from '@/lib/supabase/server'

/**
 * Send testing notification to appropriate users
 */
async function sendTestingNotification(params: {
  projectId: string
  deliverableId: string
  type: NotificationType
  title: string
  message: string
  deliverableTitle: string
}): Promise<void> {
  const supabase = await createClient()

  // Determine who should receive this notification based on type
  let roles: string[] = []
  let excludeUserId: string | null = null

  switch (params.type) {
    case 'testing_ready_dev':
      // Notify the dev assigned to the deliverable
      const { data: devAssignment } = await supabase
        .from('deliverables')
        .select('assigned_to')
        .eq('id', params.deliverableId)
        .single()

      if (devAssignment?.assigned_to) {
        await supabase
          .from('notifications')
          .insert({
            user_id: devAssignment.assigned_to,
            type: params.type,
            title: params.title,
            message: params.message,
            project_id: params.projectId,
            deliverable_id: params.deliverableId,
          })
      }
      return

    case 'testing_ready_admin_int':
      // Notify admins and internal team
      roles = ['admin', 'internal']
      break

    case 'testing_ready_client':
      // Notify client and DFY if applicable
      roles = ['client', 'dfy']
      break

    case 'testing_passed':
    case 'testing_failed':
      // Notify admins and internal team about results
      roles = ['admin', 'internal']
      // Also notify the dev who assigned the deliverable
      const { data: devInfo } = await supabase
        .from('deliverables')
        .select('assigned_to')
        .eq('id', params.deliverableId)
        .single()

      if (devInfo?.assigned_to) {
        excludeUserId = devInfo.assigned_to
      }
      break

    case 'testing_escalated':
      // Notify admins and client that test was escalated
      roles = ['admin', 'internal', 'client']
      break

    default:
      return
  }

  // Get all users with the specified roles who have access to this project
  const { data: users } = await supabase
    .from('profiles')
    .select('id')
    .in('role', roles)

  if (!users) return

  // Filter out excluded user if specified
  const targetUsers = excludeUserId
    ? users.filter(u => u.id !== excludeUserId)
    : users

  // Create notifications for all target users
  if (targetUsers.length > 0) {
    await supabase
      .from('notifications')
      .insert(
        targetUsers.map(user => ({
          user_id: user.id,
          type: params.type,
          title: params.title,
          message: params.message,
          project_id: params.projectId,
          deliverable_id: params.deliverableId,
        }))
      )
  }
}

## Task 10: Escalation Background Job

**Files:**
- Create: `app/api/testing/check-escalations/route.ts`

**Step 1: Create API endpoint for checking escalations**

```typescript
import { NextResponse } from 'next/server'
import { createClient } from '@/lib/supabase/server'

/**
 * Check for client tests that have been in progress too long
 * This should be called by a cron job daily
 *
 * Escalation rules:
 * - Client tests in "in_progress" for 7+ days can be escalated by admin
 */
export async function GET(request: Request) {
  const authHeader = request.headers.get('authorization')
  if (authHeader !== `Bearer ${process.env.CRON_SECRET}`) {
    return NextResponse.json({ error: 'Unauthorized' }, { status: 401 })
  }

  const supabase = await createClient()

  // Find client tests that have been in progress for 7+ days
  const sevenDaysAgo = new Date()
  sevenDaysAgo.setDate(sevenDaysAgo.getDate() - 7)

  const { data: staleTests } = await supabase
    .from('deliverable_tests')
    .select(`
      id,
      deliverable_id,
      started_at,
      deliverables(
        project_id,
        title
      )
    `)
    .eq('stage', 'client')
    .eq('status', 'in_progress')
    .lt('started_at', sevenDaysAgo.toISOString())

  if (!staleTests || staleTests.length === 0) {
    return NextResponse.json({ escalated: 0 })
  }

  // Mark as eligible for escalation
  // (Admin still needs to explicitly escalate)
  await Promise.all(
    staleTests.map(test =>
      supabase
        .from('deliverable_tests')
        .update({
          notes: `[ELIGIBLE FOR ESCALATION] Started ${new Date(test.started_at).toLocaleDateString()}`,
        })
        .eq('id', test.id)
    )
  )

  return NextResponse.json({
    escalated: 0,
    eligibleForEscalation: staleTests.length,
    tests: staleTests.map(t => ({
      testId: t.id,
      deliverableId: t.deliverable_id,
      startedAt: t.started_at,
    })),
  })
}
```

# Testing System Documentation

## Overview

The testing system provides a structured, multi-stage workflow for validating deliverables before they are marked complete. Each deliverable goes through three sequential testing stages:

1. **Developer Self-Testing** (90%) - Dev validates their own work
2. **Admin/INT QA Review** (90-95%) - Internal team conducts thorough testing
3. **Client UAT** (95-100%) - Client performs acceptance testing

## How It Works

### Triggering Testing

When a deliverable's hill chart position reaches 90%:
1. The Testing tab becomes visible in the project
2. A dev test session is auto-created
3. The assigned dev receives a notification
4. AI-suggested checklist items are generated

### Testing Stages

#### Stage 1: Developer Self-Testing
- **Who:** The dev assigned to the deliverable
- **What:** Run through checklist, mark items pass/fail
- **Outcome:** If all pass → Admin/INT notified. If any fail → Dev fixes and retries.

#### Stage 2: Admin/INT QA Review
- **Who:** Admins and internal team members
- **What:** Thorough testing including edge cases and security
- **Outcome:** If all pass → Client notified. If any fail → Blockers created, dev notified.

#### Stage 3: Client UAT
- **Who:** Client (and DFY if applicable)
- **What:** Acceptance testing against original requirements
- **Outcome:** If all pass → Deliverable at 100%, complete!
- **Escalation:** After 7 days, admin can escalate/approve on client's behalf

### Failed Items

When a checklist item fails:
1. A blocker is auto-created linked to that item
2. The deliverable stays at current position (doesn't regress)
3. The item is marked for re-testing
4. When the blocker is resolved, the same tester re-tests only that item
